# Stage Two B1: stopped before SCPI on unsolicited host traffic

B1 reached the temporary host-address transition and stopped before opening a TCP
connection. Assigning the address caused existing Mac services to emit unsolicited
traffic on the isolated segment. The stop gate detected the first unexpected UDP
frame, removed the temporary address, and stopped the recorder gracefully. There
was no SCPI request or response, so no physical model, serial or software-version
identity was obtained. The operator reported an unchanged UI and no prompt.

## Authorized boundary and preflight

The operator authorized contact for the previously proposed one-query B1.
Tasking was admitted after preview inspection and committed/pushed as `6e030f0`
before execution. The [endpoint decision](scpi-endpoint-decision.md) supplied
implementation-derived TCP port 5555 and LF framing; the command remained one
parameterless `*IDN?`, with no retries or additional management.

The fresh privileged baseline confirmed the previously identified TS4 Ethernet
interface and MAC, active carrier, no IPv4/IPv6 address on that interface, inactive
host IPv4/IPv6 service configuration, and the ordinary default route elsewhere.
IPv4 and IPv6 forwarding were zero; packet filtering was disabled with no active
NAT path; Internet Sharing was disabled; the interface was not a bridge member.
No DHCP responder or BPF capture user was active. The prior one-hour lease still
had over twenty minutes remaining, and the operator confirmed physical continuity
and an unchanged UI. No lease renewal was performed.

An initial host supervisor launch exited at a Python import before starting any
capture or network action. Launch construction had resolved the virtual-environment
interpreter symlink into the base interpreter. Its failed log was preserved; the
corrected launch retained the virtual-environment path and passed offline import
checks. This was a host preparation failure, not a failed physical recorder or
an additional specimen experiment.

## Captured intervention and stop

The corrected recorder normalized only its own inherited signal state. Its
receipt shows an empty blocked-signal mask before exec. Capture used Ethernet
link type, a 262144-byte snapshot length, no BPF filter, immediate delivery,
packet-buffered writes and live text decoding. The header and live decoder were
verified before the address gate was released; no frames were stored at that gate.

The baseline socket inventory associates port 57621 with Spotify, consistent with
its payload prefix. The capture does not independently attribute every other
packet to a process. These were emissions caused by introducing an OS-visible
address; they were not generated by a SCPI client. They still crossed the
experiment's permitted traffic boundary and therefore required stopping.

The observer stopped at the first unexpected UDP frame, while the raw recorder
retained the additional frames already emitted before cleanup. No query gate was
released. There are zero TCP frames, zero connection attempts, and no request or
response artifacts. No scope-originated frame was recorded in this short capture.
This does not establish that the instrument ignored the broadcasts or that no
later response was possible. UI continuity does not prove absence of internal
state changes caused by receiving network traffic.

## Recorder and restoration evidence

The recorder exited with status zero after SIGINT and preserved all three final
counters: **7 captured, 7 received by filter, 0 dropped by kernel**. Independent
pcap parsing found seven full-length records and no trailing partial record.
The raw and sealed copies match. These counters support this recorder's observed
capture result; they are not a universal guarantee against losses elsewhere.

The temporary host address and directly connected scope-subnet route were removed
under capture. A final audit found the interface unnumbered, carrier retained,
forwarding still disabled, default route unchanged, no sharing/NAT/bridge path,
and no BPF users. The full network preferences and interface-inventory property
lists are byte-identical before and after. No host security policy, global
service setting, scope lease, physical cable or instrument control was changed.

The recorder correction has now also succeeded on the physical Ethernet capture
path. The failed identity attempt should not be confused with a recorder failure.

The manifest binds baseline/final audits, exact private fixture, failed and
corrected launch logs, event timeline, raw capture/live decode, packet analysis,
verification and the operator UI observation. Earlier stages remain unchanged.

There is no returned identity to reconcile against the corpus. The stock `.26`
implementation evidence still supports 5555/LF as the candidate endpoint; this
run neither confirms nor contradicts its applicability to the physical specimen.
Installed firmware, serial text and physical SCPI availability remain unknown.

**Decision: stop for operator review; do not retry B1 on the specimen.** The next
useful work is a host-only control of address-triggered traffic away from the
specimen interface. It should establish a quiet, bounded communication method
before another physical attempt. A dedicated isolated network stack or packet-level
client may avoid exposing an address to ordinary desktop services, but either
needs separate design and host-only validation. Do not disable global services
or security controls merely to make the current method proceed. No successor
physical task is admitted by this conclusion.
