# Stock whole-loader validation decision

The filesystem fixture now has independently verified complete reads under the intended application identity.
The prior denial and the successful two-file label control use the same probe APK and stock files; the latter also
preserves system_server continuity, file bytes, directory metadata, and the four deliberate absences.
That resolves the environmental ambiguity which prevented a meaningful stock loader experiment.

Proceed with one bounded stock initialization run through the first three calibration loaders. Keep the already
controlled native observer unchanged. Validate the inherited 466-store initialization prefix, then observe whole
LSB and vertical payload transfers and the absent ADC-file outcome. Stop at `0x333ba8`, before the call to
`SetADCParameter(0)`. No additional modeled register response is needed for this candidate.

The expected returns are 192, 1,794,240, and -1. These are fixture-conditional static predictions until witnessed.
Capture actual entry ADC bytes and require equality with the terminal bytes, rather than silently imposing the
static zero-fill expectation. Capture complete terminal LSB and vertical destinations and compare them with the
independently hashed stock payloads. The main-thread checkpoints must be accompanied by terminal thread-group
convergence; an unexpected access, clone, status, signal, or deadline ends this candidate without a changed retry.

Adapt the verifier for stock addresses and lifecycle. The existing tail verifier ends too early and pins the older
binary; the private loader verifier assumes private layouts and generated patterns. Reuse their semantic checks
with an explicit stock profile, independently bound to the installed library and executed observer bytes.
Verify the complete inherited prefix, checkpoint ordering and register preservation, all five capture files,
full thread cleanup, final guest health, and fixture preservation. Test altered evidence before the run.

The mounted fixture is discarded with the disposable guest after final file witnesses. This decision does not
require or claim an unmount restoration. Successful file loading would establish a stock software-state transition;
it would not establish calibration accuracy, physical instrument behavior, or acquisition.

After this experiment, evaluate the next initialization dependency as a whole subsystem: recover deterministic
operations statically and reserve runtime questions for selectors, returned device state, asynchronous behavior,
and unresolved boundaries. Do not return to one experiment per predictable write.
