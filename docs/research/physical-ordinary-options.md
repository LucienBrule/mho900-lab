# Physical ordinary-option transitions

The as-delivered stock APK and native library are preserved. The ordinary catalog
uses exact requests previously accepted by the specimen-derived disposable guest;
no request is regenerated on the instrument. This is research-produced option
material, not a claim of vendor-issued entitlement. BND is excluded because its
bundle behavior can remove individual saved files.

Each transition has a separate full Ethernet capture, host baseline/restoration,
raw SCPI request/response, before/after logical data, process/boot identity and UI
screenshots. The controller sends exactly one install request without automatic
retransmission, then bounds status observation. Independent verification reconciles
the SCPI TCP byte streams with retained requests/responses and file/status effects.

The preservation baseline includes the earlier complete storage acquisition,
unit-specific logical corpus and separately paired FRAM readback. A live raw storage
image is not claimed to be atomic or a tested full restoration procedure.

## Catalog conclusion and reboot checkpoint

All ten intended ordinary options are now enabled through the documented SCPI
installer. Every candidate required one request and one successful status poll.
Each added only its own saved license, matching the accepted guest bytes; earlier
licenses, key/vendor files, identity and the running stock application remained
unchanged. Every before/after screenshot was inspected and showed normal
acquisition UI without a prompt. BND remains disabled. No reboot has yet been
counted as persistence evidence in this catalog conclusion.

The separately admitted reboot checkpoint uses one normal reboot, a fresh captured
DHCP ACK, three complete identity/status transcripts, exact protected-file checks
and a stable postboot process through a sixty-second observation interval. The
fixed stock observer must then independently establish repeated17/17 from sixteen
read-only process-memory bytes. Host controls passed for carrier loss, bounded
DHCP RELEASE handling, malformed streams and single reboot/root-call limits.

ordinary options remained enabled and BND remained disabled, both immediately
