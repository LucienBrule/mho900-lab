# What survived the reboot

Draft, 2026-09-29. Based on the [overnight research handoff](../research/overnight-entitlement-handoff.md).

“Persistence works” needs a subject. A file can survive while the application ignores it. A query can remain
true because it is hard-coded. A process can reload a value that was silently regenerated by its harness.

The MHO900 guest experiment therefore asked several separate questions. Did unchanged stock software accept
the token? Did it write a license? Did a new process validate that saved license? Did the same result survive
an actual guest reboot without another installer or token producer call?

The final individual-option experiment answered all four. Ten licenses were accepted, and their consumer
paths were observed again during reload. The guest's boot identity changed. Twenty-two canonical files,
including licenses, the synthetic key fixture and serialized private state, were byte-identical across the
final installation and both reload phases.

The catalog contained thirteen true entries, but that did not mean thirteen licenses had been installed.
Three entries were already true through built-in query policy. Counting transitions and recording the
original baseline prevented a misleading headline.

The storage boundary mattered just as much. Stock serialization ran, but the harness explicitly saved its
MemFile representation to a guest file. That demonstrated a useful component persistence path. It did not
show that the physical instrument would automatically flush its external FRAM, recover from a sudden power
loss, or advance trial timers in the same way.

A complete image of the instrument's main storage would not settle every one of those questions. Application
RAM, mapped register state and external nonvolatile storage are distinct domains. Two live block-device
reads can also differ while the instrument is running. A large image is evidence of what was read, not an
automatic guarantee of a frozen, complete or restorable instrument state.

The separate capability experiment made another boundary visible. A derived copy selected a different
capability record while preserving public model identity and the existing license seed. Its enum-18 result
survived guest reboot. That established software policy selection; it did not measure a 1 GHz analog transfer
function. Keeping those claims separate makes both results more useful.

A good persistence experiment records what supplied the initial state, what was allowed to regenerate it,
which process and boot actually changed, and which exact files survived. It also names the storage behavior
that remains modeled. Those details let a later physical experiment test a small remaining assumption rather
than rediscover the entire software path.
